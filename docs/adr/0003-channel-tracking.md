# ADR-0003: 채널 추적 — 쿼리스트링 대신 링크 코드

## 상태
채택

## 배경
같은 폼을 인스타그램·X·유튜브·스레드 4개 채널에 배포하고 채널별 성과를 구분해야 한다.
흔한 방식은 `?utm_source=instagram` 같은 쿼리스트링이지만, 사용자가 URL을 편집해
지울 수 있고 일부 SNS는 링크의 쿼리스트링을 잘라내거나 리다이렉트로 유실시킨다.

## 결정
채널 구분은 **채널별 고유 링크 코드**로만 한다. 쿼리스트링은 쓰지 않는다.
- 폼마다 채널당 8자리 코드를 발급하고 `/f/{code}`로 배포한다.
- 방문 기록·제출 모두 코드로 채널을 판정한다(`Channel` enum 4종 고정).
- 공개 폼 렌더 시 서버가 업로드 HTML의 `<form>`에 `action`(제출 URL)과
  `__link`(코드) hidden 값을 **jsoup으로 주입**한다. 제출은 이 `__link`로 링크를
  역조회해 `link_id`/`channel`을 결정한다.
- 같은 `form + channel` 조합으로 재발급을 요청하면 **기존 코드를 그대로 반환**한다(멱등).

## 근거
- 코드는 경로의 일부라 사용자가 임의로 바꾸기 어렵고, 잘못된 코드는 404로 명확히 실패한다.
- `utm_source`는 조작·유실 위험이 있어 채널별 성과의 신뢰도를 떨어뜨린다.
- 채널을 hidden 값으로 서버가 주입하므로 클라이언트가 채널을 위조할 여지를 줄인다.
- 멱등 발급은 "채널 4개 링크 일괄 발급" 버튼을 여러 번 눌러도 코드가 중복 생성되지
  않게 하여 배포 URL의 안정성을 보장한다.

## 한계 / 후속
- 코드는 `SecureRandom` 8자리(36진)로 생성하고 충돌 시 재시도한다. 발급량이 매우
  커지면 코드 길이를 늘려야 한다(마이그레이션으로 컬럼 확장).
- 사용자가 코드를 서로 공유하면 채널 귀속이 부정확해질 수 있으나, 쿼리스트링보다
  왜곡 여지가 작다.
