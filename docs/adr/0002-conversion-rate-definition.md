# ADR-0002: 전환율 정의 — 분모를 방문자로

## 상태
채택

## 배경
과제는 "채널별 전환율 확인"을 요구하지만 **전환율의 분모**를 명시하지 않았다.
분모 후보는 방문(PV, 페이지 조회 수)과 방문자(UV, 고유 방문자 수) 둘이다.
방문을 분모로 쓰면 사용자가 새로고침만 해도 분모가 늘어 전환율이 왜곡된다.

## 결정
**전환율 = 신청 ÷ 방문자 × 100.** 분모는 방문(PV)이 아니라 **방문자(UV)**로 한다.
- 방문(visits) = 폼 페이지 조회 수 (새로고침 포함, 매번 1행)
- 방문자(visitors) = first-party 쿠키 `vid` 기준 고유 방문자 수 (`visitor_id` DISTINCT)
- 신청(submissions) = 제출 완료 건수
- 계산은 `StatsService.conversionRate()` 한 곳에서만 수행하고 소수점 1자리로 반올림한다.

## 근거
- UV 기준이 "몇 명 중 몇 명이 신청했는가"라는 마케팅 전환의 상식적 정의에 부합한다.
- PV 기준은 새로고침·뒤로가기로 부풀려져 채널 간 비교를 신뢰할 수 없게 만든다.
- 방문과 방문자를 **모두 저장**하므로, 필요하면 PV 기준 전환율도 후속 계산이 가능하다.
  (정의만 바꾸면 되며 데이터 손실이 없다.)

## 한계 / 후속
- **0 나누기 방어 필수**: 방문자가 0이면 전환율은 `0.0`으로 고정한다
  (`visitors == 0 ? 0.0 : ...`).
- `vid`는 쿠키 삭제·시크릿 모드·다기기 사용 시 동일인을 다른 방문자로 셀 수 있다.
  로그인 없는 공개 폼의 구조적 한계이며, 서버 측 지문·인증 기반 식별은 과제 범위 밖이다.
- 전환율이 100%를 넘지 않도록 방문자 수는 항상 신청 수 이상이어야 한다
  (E2E 테스트가 이 불변식을 검증).
- **채널별 방문자 합계가 캠페인 방문자보다 클 수 있다.** 한 방문자가 서로 다른 채널 링크로
  각각 접속하면 채널별 방문자에 중복 계산되기 때문이다(실측 예: 캠페인 방문자 4명인데,
  인스타·유튜브 양쪽으로 방문한 1명 때문에 채널별 방문자 합은 5명). 이는 각 채널 성과를
  독립적으로 측정하기 위한 **의도된 동작**이다. 채널별 방문자를 합산해 캠페인 방문자로
  쓰지 않으며, 캠페인 방문자는 전체 `visitor_id` DISTINCT로 따로 집계한다.
