# ADR-0006: 템플릿 / 캠페인 / 폼 3계층 분리

## 상태
채택

## 배경
과제 문서는 "AI로 만든 **HTML을 등록**하는 것"과 "그것으로 **신청 폼을 생성**하고
채널별로 배포·집계하는 것"을 별개의 단계로 기술한다. 이를 한 덩어리로 모델링하면
같은 디자인을 재사용하거나 성과를 캠페인 단위로 묶기 어려워진다.

## 결정
도메인을 3계층으로 분리한다.
- **템플릿(`html_templates`)**: 디자인 자산. 재사용 단위. 운영자가 등록한 raw HTML.
- **캠페인(`campaigns`)**: 성과 측정 단위. 통계(방문/방문자/신청/전환율)의 집계 경계.
- **폼(`forms`)**: 배포 실물. 캠페인에 속하고 템플릿을 참조하며, 채널별 링크가 달린다.

폼의 소유권은 **소속 캠페인의 소유권으로 판정**한다(`Form`은 `user_id`를 갖지 않고,
`FormService.getOwned`가 캠페인 소유권을 경유해 검증). 통계는 캠페인에 소속된 모든
폼의 방문/신청을 합산한다.

## 근거
- 템플릿을 분리하면 하나의 디자인을 여러 캠페인·폼에서 재사용할 수 있다.
- 캠페인을 성과 단위로 두면 "캠페인별·채널별 전환율"이라는 요구가 자연스럽게 집계 경계와
  일치한다.
- 폼에 `user_id`를 중복 보유하면 캠페인과 불일치할 여지가 생긴다. 소유권을 캠페인
  한 곳에서만 판정하면 권한 검증의 단일 진실 소스가 유지된다.
- "범용 폼 빌더는 과제 범위 아님"과도 정합적이다. 폼은 템플릿+채널의 조합일 뿐,
  필드를 편집하는 빌더가 아니다(필드는 템플릿에서 자동 추출 — ADR-0004).

## 한계 / 후속
- 폼이 여러 캠페인에 걸치는 요구(폼 공유)는 현재 모델에서 지원하지 않는다.
  필요해지면 다대다 매핑을 도입해야 하나, 현 요구에는 과설계다.
- 템플릿 수정 이력·버전 관리는 범위 밖이다.
